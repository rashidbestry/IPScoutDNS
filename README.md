# IPScoutDNS

IPScoutDNS discovers working IPv4 addresses using upstream DNS resolvers and TCP/TLS reachability checks. It runs as an Active DNS server or a Passive scheduled domain resolver.

## Supported releases

Desktop/server binaries are published for Linux and Windows on `amd64` and `arm64`. macOS binaries are not published.

Tagged releases also build an architecture-specific OpenWrt APK for `rockchip/armv8` (`aarch64_generic`), targeted and tested for OpenWrt 25.12.5 on the FriendlyElec NanoPi Zero2. OpenWrt package metadata is generated by the matching SDK; the package is not marked architecture-independent.

## Requirements

- Go version specified in `go.mod` to build from source.
- The system `ping` utility on `PATH` for ping-based reachability checks. ICMP availability and permissions depend on the operating system.

## Build and run

Build for the current machine:

```sh
go build -o ipscoutdns .
```

Run with an explicit config file:

```sh
go run . --config ipscoutdns.conf
```

The sample config listens on port 53. Use a port above 1024 if the operating system requires elevated privileges for low ports.

## Operating modes

Every config must set exactly one `mode`: `active` or `passive`.

Active mode listens for UDP/TCP DNS requests. It resolves allowed A queries using the existing DNS/probing pipeline and cache; disallowed A queries and non-A queries are forwarded to fallback DNS. The allowlist contains regular expressions:

```ini
mode=active
active_domains_file=active-domains.txt
```

For example, `^([a-z]+\.)?example\.com$` matches `example.com` and `api.example.com`; `.*` allows all domains. An empty allowlist matches nothing. A missing file or invalid regex stops startup. The allowlist is loaded at startup.

Passive mode runs without DNS listeners or fallback forwarding. It reads literal hostnames, discovers candidate IPs, probes them, and writes the same reachable/unreachable output files:

```ini
mode=passive
passive_domains_file=passive-domains.txt
passive_resolve_interval=24h
passive_resolve_parallel=16
```

Both modes use the same `ipscoutdns.conf`: change `mode=active` to `mode=passive` and run `go run . --config ipscoutdns.conf`. Upstream resolvers, interface selectors, probe settings, and output paths are shared. Edit `passive-domains.txt` to choose the domains. It accepts one ASCII hostname per line (punycode for international names), blank lines and `#`/`;` comments. Names are lowercased, a trailing dot is removed, and duplicates are resolved once per pass. Regexes, wildcards, URLs and IP addresses are rejected.

Set `passive_resolve_time=03:00` to run daily at 03:00 in the machine's local timezone. This overrides the interval schedule and waits for the next occurrence after startup. Missed runs are skipped. Before each pass, contents of the dedicated output directory on Linux/OpenWrt (including subdirectories) are cleared, except saved console log files; the directory remains. On Windows, only configured output files are cleared, preserving the executable and its logs folder. Cleanup errors stop passive mode. Keep Linux/OpenWrt input files outside the output directory. With `passive_resolve_time` blank (the default), the first pass starts immediately. After a complete pass, the daemon waits `passive_resolve_interval` (default `24h`), reloads the domain list, and starts another pass. Passes never overlap. A missing/invalid list fails startup; a later list error is logged and that pass is skipped. An empty list is allowed and performs no work until the next reload.

`passive_resolve_parallel` (default `16`) limits concurrent **domain** jobs. `parallel_tests` still limits concurrent IP probes **within each domain**, so 16 domain jobs with 16 probes each may run up to 256 probes concurrently. Reduce either setting for smaller devices. Every Passive pass performs fresh DNS discovery and probing regardless of the Active cache TTL. Working-IP selection prefers TLS, then the enabled HTTP fallback, just as in Active mode.

Both modes automatically store enabled output files in `/tmp/ipscoutdns/` on OpenWrt (including distributions declaring `ID_LIKE=openwrt`), `/temp/ipscoutdns/` on other Linux systems, and the executable's directory on Windows. The directory is created at startup. Output settings choose filenames: any configured parent directory is replaced by the OS-selected directory, and blank optional settings remain disabled. Input paths are unaffected. Startup config logs show the resolved output paths.

Set `save_logs=true` to also save startup/config and runtime messages to dated `ipscoutdns_log_YYYY-MM-DD_HH-MM-SS.txt` files. This is enabled in the sample config and defaults to `false` when omitted. Saving works independently of `logs_enabled`, which controls runtime console output. Windows creates files in a `logs` folder beside the executable and never copies them elsewhere. Linux/OpenWrt stores them directly in the runtime output directory. Passive cleanup preserves saved logs, and host-file copies exclude them.

`log_max_size=10MB` (default 10,000,000 bytes) rotates before the next message would exceed the limit. A single oversized message stays intact in its own file, so that file can exceed the limit. Sizes accept positive whole bytes or `B`, `KB`, `MB`, `GB`, `KiB`, `MiB`, and `GiB` suffixes. `log_keep_files=7` (default seven) retains the newest files, including the current file. Only regular files with IPScoutDNS's dated log filename format are removed; unrelated files and directories remain. Same-second starts and rotations add increasing numeric filename suffixes. Windows applies retention when opening or rotating a log. Rotation and retention are inactive when `save_logs=false`.

Linux/OpenWrt copies the current log and pending rotated logs to `/etc/ipscoutdns/logs/`, updating the same destination filename as a log grows. Unchanged completed logs already copied to that destination are not rewritten. Active mode uses the separate `active_log_copy_interval=1h` setting (default one hour); the first copy waits a full interval, and subsequent intervals begin after the previous copy finishes. Passive mode copies after resolving/probing and its completion/schedule message, before the next wait; canceled passes are not copied. Retention runs in the source and archive directories after a successful copy. Uncopied source files, including closed logs with new contents since their last copy, are protected and can temporarily exceed `log_keep_files`. Copy failures preserve that backlog for the next scheduled attempt.

On Linux/OpenWrt, regular output files directly in the selected directory are copied to `/etc/ipscoutdns/` with the same filenames. Windows does not copy outputs in either mode; files stay beside the executable, no copy logs are emitted, and `active_copy_interval` is ignored. On Linux/OpenWrt, Passive mode copies after all domain jobs and probes finish, before waiting for the next pass. An interrupted pass is not copied. Active mode uses `active_copy_interval=1h` (the default); set another positive duration such as `6h` to change it. The first active copy waits a full interval after startup, and each subsequent interval starts after the previous copy finishes. Copies take a snapshot under the output lock and replace individual destination files using temporary files, retaining the source files and unrelated destination files. Missing or empty source directories have nothing to copy. Copy failures are logged, and the service continues to the next scheduled attempt.

`hosts_max_ips_per_domain` defaults to `8` in both Active and Passive mode. Each fresh domain check stops launching probes once that many successful candidates are found; failures do not count toward the limit. Probe batches use at most `parallel_tests` workers and shrink to the remaining success quota, so even concurrent successes cannot exceed the limit. Skipped candidates retain unknown status. The latest completed check replaces that domain's host mappings, preventing old addresses from accumulating across resolutions or restarts. Subsequent Passive passes still recheck the domain, and Active cache hits need no probes. Set `hosts_max_ips_per_domain=0` to restore unlimited probes and append-style host output. Higher limits may produce truncated DNS answers for clients with small UDP response sizes.

Domain checks try TLS first, on `tcp_port` (normally 443). If no candidate passes TLS, they try HTTP on port 80 using the same route, proxy, source interface, timeout, and worker limit. HTTP probes send a `HEAD` request with the domain's hostname to each candidate IP. Valid HTTP responses, including redirects and error statuses, count as reachability; redirects are not followed. If every TLS TCP connection fails, the existing one-round TCP retry runs before the HTTP fallback. Failed checks can therefore take additional probe rounds.

`reachable.domains` records domains with at least one successful TLS or enabled HTTP probe. With TLS or HTTP enabled, TCP or ICMP alone only classifies IP reachability. With both service probes disabled, the enabled TCP or ICMP check also determines domain reachability. A success immediately removes the domain from `unreachable.domains`. If no candidate passes TLS and the HTTP fallback also fails, the domain immediately moves to `unreachable.domains`. With `http_probe=false`, failure to find a TLS-ready candidate is sufficient. DNS lookups without IPv4 candidates and canceled checks are inconclusive and leave the previous domain status unchanged. Existing output entries remain until domains are checked again.

This is a breaking config change: `mode` is required and `domains_file` has been removed. Replace it with `active_domains_file` for existing DNS-server deployments. Passive configs require `passive_domains_file`; listener/fallback addresses and the fallback interface are unused in that mode. Both modes require at least one upstream resolver.

`reachable.hosts` appends `IP domain` pairs during runtime for candidates that pass the enabled selection probes, and on cache hits for previously successful pairs. With the default settings, this requires TCP plus TLS or the HTTP fallback. It retains previously observed pairs and avoids duplicate writes within the running process.

`http_probe=true` enables HTTP fallback when no candidate passes TLS. It defaults to `true` when omitted. Active mode prefers a TLS-ready IP; if none passes TLS, it returns and caches an HTTP-ready IP when HTTP probing is enabled. DNS fallback is used when neither enabled service probe succeeds. Both Active and Passive mode record successful TLS or HTTP candidates in `reachable.hosts` and mark the domain reachable. Working-IP and cache-hit logs include `[TLS]` or `[HTTP]` to identify the successful probe; HTTP success does not guarantee HTTPS will work. Set `http_probe=false` to skip HTTP checks and require TLS while `tls_probe=true`. With TLS disabled, selection requires HTTP if enabled, otherwise TCP if enabled, otherwise ICMP. All four probe switches default to `true`. TLS and HTTP still establish TCP connections when `tcp_probe=false`; that switch disables TCP-only checks. All probes disabled leaves reachability unknown and uses DNS fallback. ICMP remains disabled on proxy routes.

With `tcp_route=direct`, after TCP failure, ICMP checks try up to three single-packet pings and stop on the first success. Each attempt waits up to one second for the reply, with a two-second process deadline. Failed attempts are logged. With `tcp_route=proxy`, ICMP is skipped entirely and IPs whose TCP checks fail are marked unreachable. This applies in both Active and Passive mode. A successful TCP or direct ICMP recheck removes the IP from `unreachable.ips`; previous entries remain until the service checks that IP again.

## Configuration lookup

The `--config` argument takes precedence, followed by `IPSCOUTDNS_CONFIG`, then the legacy `IPSELECTOR_CONFIG` environment variable. Without an explicit path, IPScoutDNS checks `ipscoutdns.conf` in the current directory. On Unix it also checks `/etc/ipscoutdns.conf`; on Windows it checks the per-user config directory under `IPScoutDNS/ipscoutdns.conf`.

Relative input paths in the config, including the domains files, are resolved from the process working directory. Output filenames are placed in the OS-selected directory described above, independently of the working directory.

Interface selectors bind traffic to a local source IP. They do not guarantee that traffic is pinned to a physical network device.

## OpenWrt

Install the release APK on OpenWrt 25.12.5 `rockchip/armv8` devices:

```sh
apk add --allow-untrusted ./ipscoutdns-<version>-rockchip-armv8-aarch64_generic.apk
```

The package installs the binary at `/usr/bin/ipscoutdns`, config at `/etc/ipscoutdns.conf`, regex patterns at `/etc/ipscoutdns/active-domains.txt`, literal hostnames at `/etc/ipscoutdns/passive-domains.txt`, and a procd service at `/etc/init.d/ipscoutdns`. The service is not enabled automatically:

```sh
/etc/init.d/ipscoutdns enable
/etc/init.d/ipscoutdns start
```

The package generates its OpenWrt config and domain lists during packaging from the repository-root `ipscoutdns.conf`, `active-domains.txt`, and `passive-domains.txt`. The config applies router-specific listener, route, and file-path overrides and listens on `127.0.0.1:5354` to avoid conflicting with dnsmasq. The package does not modify dnsmasq settings; configure DNS forwarding separately if desired.

The packaged config defaults to `mode=active`. To use Passive mode, set `mode=passive` in `/etc/ipscoutdns.conf`, edit `/etc/ipscoutdns/passive-domains.txt`, and restart the service. Keep output paths under `/tmp/ipscoutdns/` in either mode.

All writable runtime output files are configured under `/tmp/ipscoutdns/`. The service creates this directory at startup. OpenWrt clears `/tmp` on reboot. The package uses the router's `/bin/ping` and depends on `ca-bundle` for TLS certificate validation.
